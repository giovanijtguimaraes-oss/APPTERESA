# RCA — Deploy run 5d37ed0d-6a61-4888-a674-00ba25b6bfe5 (TERESA / wound-healing-1)

## Outcome
Deploy FAILED at `build_image`, specifically the **EAS OTA update lane** (Metro bundling via `eas update`). The backend Docker lane is irrelevant to this failure. Nothing was promoted — the previous healthy run (`9a07d091-...`) is still live at https://wound-healing-1.emergent.host.

## Root cause (CONFIRMED)
Metro could not resolve the `buffer` module while bundling the JS:

```
[expo-cli] iOS Bundling failed ... node_modules/expo-router/entry.js
[expo-cli] Error: Unable to resolve module buffer from /workspace/frontend/src/services/ble.ts:
[expo-cli]   buffer could not be found within the project or in these directories: node_modules
  > 654 |   const { Buffer } = require('buffer');
 src/services/ble.ts
  | import "buffer"
```

Verified directly against the pulled source in the eph sandbox:
- `frontend/src/services/ble.ts:654` → `const { Buffer } = require('buffer');` (inside `decodeBase64`, fallback when `globalThis.atob` is unavailable).
- `grep 'buffer' frontend/package.json` → **not present** in dependencies.
- `frontend/node_modules/buffer` → **does not exist**.

`buffer` is a Node core module name but is NOT auto-polyfilled in the React Native / Metro runtime — it must be an explicit npm dependency. Because it is neither declared nor installed, `eas update` (Metro) fails to bundle and the whole Cloud Build exits 1.

Note: the `git rev-parse --show-toplevel exited with non-zero code: 128` lines in the log are harmless warnings (EAS falling back to CWD as project root), NOT the failure.

## Why this didn't surface earlier
`expo-doctor`, ESLint, and the web-preview regression do not exercise the production Metro bundle. The `require('buffer')` path only triggers at bundle time (and only when `globalThis.atob` is absent), so it slipped through until the EAS OTA bundling step.

## Fix (Source — E1 to apply in the preview/source env)
Add `buffer` to the frontend dependencies so Metro can resolve it:

```
cd /app/frontend
yarn add buffer@^6.0.3
```

This adds `"buffer": "^6.0.3"` to `frontend/package.json` and installs it into `node_modules` + `yarn.lock`. `buffer@6.0.3` is the standard React Native-compatible build and matches the existing `Buffer.from(b64, 'base64')` usage.

Optional hardening (not required for the build to pass): import `Buffer` at the top of `ble.ts` (`import { Buffer } from 'buffer';`) instead of the inline `require`, so it's statically resolvable.

After applying, re-trigger the deploy. The Metro/EAS OTA lane will then bundle cleanly.
